# Audify v1.9.4 performance audit

Date: 2026-11-15
Target previously attached: Realme RMX3950IN, Android 16
Scope: cold startup, Compose work, settings entry, artwork/blur, playback cache setup

## Evidence and limitations

- Earlier physical-device cold-start measurement: `am start -W` WaitTime 3.07 s. The app launched, and the sampled frame report showed 2.38% janky frames, P50 24 ms, P90 31 ms, P95 32 ms and P99 450 ms. The sample mixed launch attempts and was not a controlled Macrobenchmark run.
- A later captured physical-device sample reported 4.56 s launch time, 5.12 s fully-drawn, 2.20% janky frames, P50 21 ms, P90 25 ms, P95 28 ms and P99 300 ms. This was not a matched before/after benchmark; do not compare it as a statistically valid improvement.
- ART reported `AudifyApp()` at 30,810 compiler instructions, over its compiler inline/optimization threshold. This is direct evidence of an oversized Compose function.
- A Perfetto trace exists at `audify-startup.perfetto-trace` (25,533,539 bytes), but it has not yet been decoded and attributed to individual slices in this report.
- A separate Android 16 API 36 x86_64 AVD (`audify_perf_clean`) was created with an 8 GB data partition and boots successfully. ADB still reports the device as `unauthorized`; no APK has been installed and no runtime claims are made. The original `audify_shots` AVD and its app data were not modified or wiped.
- No controlled v1.9.2 APK-on-same-device baseline is available. Source comparison only: v1.9.2 `MainActivity.kt` was 6,051 lines / 326,172 characters; current is 6,968 lines / 377,447 characters. This is not itself proof of runtime cost.

## Changes present in the working tree

- Removed the `startup-init.join()` barrier from `AudifyApplication`.
- Deferred Media3 audio-cache initialization until playback is actually audible; cache initialization uses a low-priority background thread and retries after a failed partial open.
- Lowered Canvas cache index replay to background priority.
- Lowered optional source bootstrap to Android background thread priority and isolated failures between SourceRegistry and InnerTubeX initialization.
- Removed synchronous Home seed-file I/O from `MainViewModel` construction.
- Split large overlay sections in `MainActivity` into separate composable restart scopes.
- Isolated About settings from the main settings state collection.
- Restored the two-layer progressive top blur/resting fade treatment, then unified the top and bottom edge treatments on `ProgressiveScrollEdgeBlur` so both use the same Haze effect implementation.
- Added first-draw `reportFullyDrawn()` reporting. This reports the first drawn frame, not the point at which remote shelves/artwork are fully hydrated.
- Made Search History and Podcast JSON hydration asynchronous with explicit protection against early writes and readiness-dependent consumers.
- Made Downloads index hydration asynchronous, replayed mutations made during hydration, and added readiness waits to offline playback and downloaded-library operations. DownloadService now avoids re-downloading a track that was already present in the hydrated index.
- Changed settings migration to use `SharedPreferences.apply()` rather than a synchronous commit, snapshots the legacy preference map once, reads the settings snapshot before dependent store initialization, and schedules automatic backup setup on IO.
- Changed LocalLibraryStore's idempotent schema marker write from `commit()` to `apply()`.
- Moved OfflinePlaylists JSON hydration to IO and replayed likes/playlist edits made while the disk snapshot is loading.
- Removed Listen Together's unconditional health request from Application startup; screen activation remains the demand trigger.
- Made LosslessOutput device callbacks and Bluetooth codec tracking lazy: application startup stores context only; the first source capability gate or Sources screen entry initializes the tracker.
- Moved the Listen Together top-bar latency/status collector into a dedicated composable restart scope so ping updates do not invalidate the full app shell.
- Moved ListenBrainz token, WebDAV/SMB connection settings and WebDAV upload-conflict collectors into dedicated dialog composables, isolating their state changes from the app shell.
