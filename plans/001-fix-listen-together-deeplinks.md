# Plan 001 — Fix Listen Together invite deep links

Written against commit **`7ca7a9653`**. Bug: invite links generated by the app can never
open the app on another device.

## Why this matters

Sachit's flagship social feature (Listen Together) invites friends with a copied link. That
flow is broken in two independent ways:

1. The app generates invite links on the host **`sachit-music.cc`**:
   - `app/src/main/kotlin/com/sachit/music/ui/screens/ListenTogetherScreen.kt:701`
   - `app/src/main/kotlin/com/sachit/music/ui/menu/PlayerMenu.kt:1437`
   - `app/src/main/kotlin/com/sachit/music/ui/screens/settings/AboutScreen.kt:195`
2. The manifest App-Links intent filter declares a **different** host with an underscore —
   `sachit_music.cc` (`app/src/main/AndroidManifest.xml:87`). Android only offers the app as
   a handler when the link's host matches a declared `<data android:host>`, so invite taps
   never reach the app even when the domain is reachable.

Additionally the repo spells the site three ways: `sachit_music.cc` (manifest), 
`sachit-music.cc` (all app code), `sachitmusic.cc` (README.md:142 FAQ link). At audit time
none of these domains resolved (DNS ENOTFOUND), which is a separate, site-owner action —
code cannot fix DNS. **Ask the human which domain is canonical before executing step 3.**
The fix below makes all code consistent so the *next* App Links verification can pass.

Relevant reader code (`handleDeepLinkIntent` in `MainActivity.kt` ~line 1545) is host-agnostic
for `/listen` paths: it accepts any host whose first path segment is `listen` and reads the
`code` query param, so no change is needed there.

## Files in scope

- `app/src/main/AndroidManifest.xml` (one `<data android:host>` line)
- `app/src/main/kotlin/com/sachit/music/ui/screens/ListenTogetherScreen.kt` (invite link)
- `app/src/main/kotlin/com/sachit/music/ui/menu/PlayerMenu.kt` (invite link)
- `app/src/main/kotlin/com/sachit/music/ui/screens/settings/AboutScreen.kt` (website link)
- `app/src/main/res/values/sachit_strings.xml` only if a string constant is introduced for
  the base URL (allowed; see step 2)
- **Out of scope:** DNS registration, README edits (markdown — human-owned), `MainActivity`
  handler logic, anything in `innertube/`.

## Steps

1. **Ask the human for the canonical site host** (recommended: `sachit-music.cc`, matching
   every in-app reference). STOP if they cannot confirm a canonical host — do not invent one.
   Record the chosen host at the top of this file as a comment in your changes.

2. **Introduce one source of truth** for the base URL. Follow existing conventions: look at
   `app/src/main/kotlin/com/sachit/music/listentogether/ListenTogetherServers.kt` for how
   server constants are already modeled (companion `defaultServerUrl` style), and
   `app/src/main/kotlin/com/sachit/music/constants/` for key/constant placement. Add the
   invite base URL as a constant (e.g. `const val LISTEN_INVITE_BASE_URL =
   "https://<canonical-host>"` in the `ListenTogetherServers` companion or a new
   `Constants.kt`-style object) and reference it from `ListenTogetherScreen.kt` and
   `PlayerMenu.kt`. Do not add UI strings for this — it is a URL, not user-facing text.

3. **Fix the manifest filter** so it matches the canonical host exactly
   (`<data android:host="<canonical-host>" />`). Keep `android:autoVerify="true"` and the
   `/listen` path prefix as-is.

4. **Fix `AboutScreen.kt`** to open `https://<canonical-host>` (same constant if reusable;
   a plain literal is acceptable if the constant location doesn't fit — do not over-engineer).

5. **Add a drift guard** so manifest and code cannot silently diverge again: a JVM unit test
   (Robolectric pattern, placed under `app/src/test/kotlin/com/sachit/music/`) that reads the
   manifest XML from disk (`File("src/main/AndroidManifest.xml")` relative to the module dir
   — verify this path resolves when tests run; if not, use the app source set via
   `android.sourceSets` is not available in unit tests, so fall back to checking the constant
   against the known manifest string in a plain JUnit test) and asserts the declared listen
   host equals the canonical constant's host. Follow the existing test style in
   `app/src/test/kotlin/com/sachit/music/utils/DevicePerformanceTest.kt` (plain JUnit4 +
   assertions, no Android framework needed for a file read).

6. **Report DNS status**: add a short note in your completion summary listing whether the
   canonical domain currently resolves and that App Links verification (`adb shell dumpsys
   package com.sachit.music | grep -A 10 "sachit"` after install, or the Digital Asset Links
   JSON at `https://<canonical-host>/.well-known/assetlinks.json`) is a follow-up the human
   must do server-side.
