# Audify 1.8.10

Audify 1.8.10 focuses on local-library reliability, backup and recovery, update handling, and settings organisation. This release also lays groundwork for a more complete local-first data architecture. Some of that work is still in progress; see **What's still being worked on** below.

## What's new and improved

- **Dedicated Backup settings:** Export and import your Audify data from a separate Backup category.
- **Automatic backup groundwork:** Added scheduled local backup support and expanded backup coverage for favourites, listening history, playlists, statistics, and supported settings. Account credentials are not included in backups.
- **Local library improvements:** Improved local favourites, listening history, and playlist handling, including guest/local use.
- **Local-first database foundation:** Added Room database entities, schema tracking, and migration infrastructure for songs, favourites, history, playlists, playlist entries, and queued sync operations.
- **YouTube sync safeguards:** Improved account/profile scoping and handling of pending playlist operations to reduce the risk of one account's queued work being applied to another account.
- **Update experience:** Improved release checking, update status, download cancellation, and cleanup of incomplete downloads. Added a dedicated Updates settings category.
- **Appearance preference:** Progressive scroll-edge blur is now OFF by default. It can still be enabled manually in Appearance settings. Existing saved preferences are preserved.
- **Playback and library integration:** Improved coordination between playback actions, local favourites, and listening-history recording.

## What's still being worked on

This is not the final local-first architecture release. Room is not yet the authoritative source of truth for every library and playlist operation; some existing flows still use the legacy local preference stores while the migration continues. YouTube synchronization also needs further real-account and account-switching validation. Backup restoration and cross-version recovery need broader device testing. Additional UI, performance, and reliability improvements remain planned.

Please treat the new database and synchronization work as an evolving foundation, not a claim that every migration or sync edge case is finished.

## Known testing limitations

The release APKs are build- and signature-verified. That does not replace testing on a range of physical phones, Android versions, TV devices, and Wear OS watches. If you encounter a regression, report it with reproduction steps and relevant device/Android details.
